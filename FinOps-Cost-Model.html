4. FinOps Optimization Levers

1 · Topic retention & compaction — Compact the event-sourced log (claims.lifecycle, policy.snapshot) and time-bound high-volume delete topics (claims.fnol 7d). Archive closed-claim history to cheap object storage for the statutory retention period.
2 · Kafka tiered storage — Move older segments off broker disk to object storage; large reduction on long-retention cost without losing replay.
3 · Right-size stream parallelism — Decisioning and fraud are the compute-heavy processors; low-volume projectors don't need the same parallelism. Tune per processor, review quarterly.
4 · API Gateway caching — Cache GET /claims/{id} with a short TTL aligned to projection lag; cuts read-model query load for repeat status checks (clients refresh the same claim repeatedly).
5 · Autoscale on consumer lag — Scale processor replicas on lag, not a fixed schedule; scale to zero for batch-like jobs (DI monthly benefit run) between runs.
6 · Observability hygiene — 90-day log retention, trace sampling, metric filters instead of logging raw payloads. Observability is often the second-largest line after Kafka — keep it deliberate.
7 · Defer ML to Year 3 — ML compute and a feature store are real cost. Rule-based decisioning/fraud carries Years 1–2 with no training-data spend and full explainability; ML earns its cost only once labeled history exists.
